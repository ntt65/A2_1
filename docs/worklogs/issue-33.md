# 이슈 #33 — 두 발표자료와 PDF

## 범위와 선행 작업

사용자는 README·Q&A 보강 후 A2_1의 발표자료를 신규 작성하도록 명시했다. 용도는 “미션 설명·구현”과 “평가 Q&A” 두 가지이고, 평가 시연 환경은 iMac의 VS Code다. 이어 PPTX 완성 후 PDF도 만들도록 지시했다. 기존 main 반영 승인에 따라 이 작업도 PR 검증 후 main에 병합한다.

선행 [PR #32](https://github.com/ntt65/A2_1/pull/32)는 main `2edda38ac1c6a177cf7496cdf9c2550ecc446b7b`에 병합되었다. 병합 후 CI `42526679507`에서 Windows 210개/19.158초, Linux 210개/21.607초, macOS 210개/45.651초 검사와 각 환경의 의존성·레지스트리 검사가 통과했다. 로컬 main을 동기화하고 깨끗한 상태에서 `codex/33-mission-evaluation-presentations`를 만들었다. [이슈 #33](https://github.com/ntt65/A2_1/issues/33)에 기초·상세·실행계획을 먼저 기록했다.

## 설계와 자료 보존

- 미션 발표는 수학 원리 → 고정 입력/shape → 구현 → 실측 → 해석의 순서로 설명한다. 기본 15항목을 먼저 다루고 Adam·Newton·정보 이론을 뒤에 둔다.
- 평가 Q&A는 질문별 답과 실측을 본문에 적으며, 세부 유도·반례·예상 꼬리 질문·실행 명령·출처는 노트로 보충한다. 긴 답변 원문은 `docs/EVALUATION_QA.md`에 있다.
- JSON 8개에서 수치를 읽고 기존 과학 그림을 사용한다. 슬라이드의 숫자는 표시용 반올림이다. 원본 PNG·JSON·노트북 및 기존 보고서는 변경하지 않는다.
- 16:9 캔버스, 한글 `Malgun Gothic`, 흰 배경에 남색/청록 강조를 사용한다. 텍스트와 표는 편집 가능하며, 수식은 이미지가 아닌 편집 가능한 Unicode 텍스트다. PowerPoint의 전용 수식 객체라고 표현하지 않는다.
- JS 원고 두 개와 공통 작성 도구는 `scripts/presentation/`에 둔다. 수학 알고리즘이나 프로젝트의 Python 의존성을 추가하지 않는다. 레지스트리는 `src/`, `tests/`, `scripts/`의 Python과 노트북을 대상으로 하므로 MJS 원고는 등록 대상이 아니다.
- 최종 PPTX를 다시 읽어 모든 슬라이드를 렌더링하고 검토한 뒤 동일 내용 PDF를 생성한다. PDF는 발표자 노트를 포함하지 않는다.

## 검증 기록

최종 제출 파일은 `docs/presentation/`의 PPTX 두 개와 같은 이름의 PDF 두 개다. JS 원고와 공통 작성 도구, 안내·수용 기준·계획·README를 함께 제출한다. 마지막 PPT 제작은 별도 v6 폴더에 `build_presentations.mjs --skip-pdf`로 실행했고, 검토 후 같은 폴더에 `--pdf-only --pdf-backend powerpoint`를 실행했다. 원본 PPTX 해시를 비교한 뒤 PDF를 만들고 네 파일을 최종 경로로 바이트 변경 없이 복사했다.

| 검사 | 미션 설명·구현 | 평가 Q&A |
|---|---:|---:|
| PPTX 슬라이드 / PDF 페이지 | 30 / 30 | 31 / 31 |
| 편집 가능한 표 | 22 | 24 |
| 발표자 노트 | 30 | 31 |
| 본문 최소 글꼴 | 18pt | 18pt |
| 노트 최소 길이(출처 포함) | 932자 | 1,302자 |
| PDF 본문 최소 추출 길이 | 97자 | 172자 |
| PPTX 크기 | 2,652,935 bytes | 1,505,893 bytes |
| PDF 크기 | 2,713,004 bytes | 1,557,775 bytes |

파일 구조·글꼴·슬라이드 크기·제목/본문 배치·표 소유 슬라이드 검사를 통과했다. 최종 PPTX를 재가져와 총61장의 PNG와 배치 정보를 만들고, 모든 슬라이드를 개별 원본 크기로 검토했다. 작은 수정 후에는 바뀐 화면을 다시 확인하고 나머지 화면의 동일 해시를 대조했다. 최종 PDF도 Poppler로 총61쪽을 별도 렌더링해 모두 개별 확인했다. 전체 PDF 페이지에서 한글 텍스트 추출과 빈 페이지 부재를 확인했다.

검토 중 발견하고 해결한 사항은 다음과 같다.

1. 13행 역전파 비교표가 가용 높이를 초과했다. 글꼴을 줄이지 않고 순전파5행·역전파8행 두 장으로 분리해 예상29/30장에서 최종30/31장으로 늘렸다.
2. 중심차분·gradient·민감도 그림을 표 위에 작게 놓으면 축과 범례가 읽기 어려웠다. 세로에 가까운 그림과 짧은 표는 좌우로 배치해 그림을 확대했다. 긴 미분값은 본문에서12유효숫자로 표시하고 노트에 원값을 유지했다.
3. `(2)`를 `(2,)`로 바로잡고, categorical의 일반 배치 `(n,K)` 유도와 실제 단일 표본 `(K,)` 구현을 구분했다. 학습률 그림의 설명을 실제 세 경로·최종 반경에 맞췄다.
4. 독립 검토에서 중심차분 Taylor 설명의 잘못된 ‘홀수차 항’ 문구를 ‘짝수차 항 상쇄’로 수정했다. Adam 보정은 각각 `1−β₁ᵗ`, `1−β₂ᵗ`로 나눈다고 명확히 했다. 기존 README·Q&A의 해당 수식과 대조했다.
5. Adam 비교의 초기점·학습률·200회를 본문에 넣고, 현재 근거 main과 기존3차 외부40% 결과가 같은 평가 시점으로 읽히지 않도록 구분했다.
6. 관리 환경에서 최종화 도구의 Windows 파일 연결 작업이 EPERM으로 차단되어 허용된 실행으로 재시도했다. 검증 도구 자체를 변경하거나 검사를 생략하지 않았다.
7. 번들 도구의 PDF 내보내기가 `#standard-fonts/Helvetica` 누락으로 실패했다. 런타임을 수정하지 않고 명시적인 PowerPoint 변환 경로를 추가했다. [공식 Open API](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentations.open)로 읽기 전용·창 숨김 상태에서 열고 [ExportAsFixedFormat API](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentation.exportasfixedformat)를 사용했다. PowerShell에서 null 범위 인자를 넘길 때 오류가 있어 실제 전체 PrintRange 객체를 전달해 해결했다. 이번에 연 문서만 닫고 변환 전후 PPTX 해시 불변을 확인했다.

로컬 검증은 MJS 세 파일의 Node 문법 검사, 원고의 모든 평가 번호·그림·소스 경로/셀 ID·자료 비변경 검사, 최종 네 파일의 구조/페이지/한글/노트/표 검사, 문서 링크, `git diff --check`, `python -m pip check`, `python scripts/update_registry.py --check`를 포함한다. 레지스트리 대상 소스는 변경하지 않았으며57파일/78개념 색인이 유효하다. 기존 PNG15개를 포함한 outputs30개와 노트북2개 총32파일의 SHA-256이 이전 감사와 같고, README의 기존 고유 링크93개가 모두 남았다. 최상위 README는974행, Q&A는800행이다.

수학 구현에 변경이 없어 동일한 로컬210개 회귀를 불필요하게 반복하지 않았다. 게시 후 정확한 최종 커밋과 병합 main에서 Windows·Linux·macOS 전체210개 CI 결과를 확인하고 이슈에 기록한다. 커밋·PR·CI·병합은 아래 완료 상태와 원격 이슈에 이어 기록한다.

## 평가 상태

외부 Naito 사전평가의 마지막 결과는 40%(6/15)다. 사전평가 기회는 소진되었으며 추가 평가나 정식 제출을 실행하지 않았다. 위 내부 검사 및 발표자료 완성은 외부 평가 점수와 별개다. 사용자 iMac의 PowerPoint·Keynote에서 직접 열어 검증했다는 주장을 하지 않는다.
