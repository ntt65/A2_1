# Step 1 작업 기록

작업일: 2026-11-08 (Asia/Seoul). 전체 계획 [#2](https://github.com/ntt65/A2_1/issues/2).
현재 작업: [#4](https://github.com/ntt65/A2_1/issues/4), 브랜치 `codex/4-shared-utils`.

## 기초계획

이후 수학 모듈이 공통으로 사용할 안정적인 수학 함수, 수치 미분, 시드, 플롯 기반,
로컬 키-값 캐시, 코드 탐색 레지스트리를 구현한다. Step 2~6 미션 모듈과 노트북은 이번 범위에 포함하지 않는다.
사용자의 순차 진행 지시를 받아 검증 완료된 Step 0 커밋 `ca2d089` 위에서 시작한다.
선행 PR #11은 자동 병합하지 않으며, 그 위에 이번 단계 변경만 검토할 수 있는 PR을 만든다.

## 상세계획

- 수학 API: 유한한 실수 입력을 float64로 처리하고 sigmoid/softmax의 shape를 유지한다.
  중심차분은 스칼라 입출력 및 양의 유한한 h를 사용한다. 난수 초기화는 실행 진입점에서만 한다.
- 플롯 API: 범위/격자/함수 출력 shape를 검사하여 공통 contour 격자와 Figure/Axes를 제공한다.
- 캐시: 입력 값·shape·dtype·매개변수·버전을 SHA-256으로 구분하고 안전한 NumPy/JSON 저장,
  원자적 교체, 손상 시 재계산, 복사 반환, 용량/정리 정책을 제공한다.
- 레지스트리: src/tests/scripts 및 미래 notebooks로 탐색을 제한한다. AST와 명시적 개념·테스트 태그로
  파일/심볼/해시/줄/의존성과 정방향·역방향 색인을 생성하고 `--check`로 변경·누락을 검사한다.
- CI: 환경·전체 unittest와 인덱스 정합성 검사를 수행한다. 선행 브랜치를 기준으로 한 PR도 검사한다.

## 실행계획

1. 수학·플롯, 캐시, 레지스트리를 겹치지 않는 파일 범위로 나누어 구현·단위 검증한다.
2. 실제 API와 예외·경계 조건을 점검하고 독립 코드 리뷰를 수행한다.
3. 발견 문제를 보완하고 전체 테스트와 환경 점검, PNG 시각 확인을 수행한다.
4. 최종 코드로 레지스트리를 갱신하고 문서·이슈의 실측 결과를 기록한다.
5. 커밋·원격 게시·PR·CI 결과와 이슈 기록까지 마무리한다.

## 검증 결과

Python 3.11.4 / NumPy 2.2.6 / Matplotlib 3.10.3, Windows 환경에서 실행했다.

| 검사 | 실측 결과 |
|---|---|
| 전체 unittest | **48개 통과**, 최종 로컬 실행 3.983초 |
| 검사 구성 | 수학·시드 14, 플롯 5, 캐시 18, 레지스트리 8, 기존 환경 3 |
| 중심차분 `(f(x+h)-f(x-h))/(2h)` | x², x=3, h=1e-5 → 6.000000000039306; 절대오차 **3.930633596382904e-11 ≤ 1e-4** |
| Softmax `exp(x-max(x))/sum(exp(x-max(x)))` | ±1e308 및 동일한 큰 logit에서 유한 출력, 표본 행 합 최대오차 **0 ≤ 1e-6** |
| Sigmoid | log-odds 기준값 0.25/0.5/0.75와 극단값 검사 통과 |
| 레지스트리 갱신·검사 | **13개 파일, 104개 심볼, 9개 개념**; `--check` 통과 |
| 의존성 | `pip check` 통과 |
| 문서·코드 형식 | 9개 문서/23개 로컬 링크, 모든 함수·클래스 docstring, 금지 라이브러리 import 검사 통과 |
| 시각 확인 | 공통 `x+2y` 등고선 PNG의 축·라벨·등고선 방향·동일 배율 확인 |

실행 명령:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

.\.venv\Scripts\python.exe scripts/update_registry.py --update
```

시각 확인용 파일 `.cache/step1-contour-smoke.png`는 캐시 폴더에 두고 제출 산출물로 추적하지 않는다.
실제 모듈의 API·shape·예외·캐시/색인 계약은 [공통 기반 사용법](../UTILITIES.md)에 정리했다.
원격 CI와 최종 커밋·PR 링크는 이슈 #4에 기록한다.

## 설계·보완 기록

- 레지스트리가 아직 없으므로 이번 초기화에 한하여 관련 경로만 탐색했다.
- 작업 이슈는 미리 발행된 #4를 갱신하여 사용하고 중복 이슈를 만들지 않았다.
- 선행 PR이 아직 열려 있으므로 검증 완료된 환경 브랜치 위에서 작업하며, 단계별 이력과 의존관계를 유지한다.
- 첫 디스크 캐시·레지스트리 검사는 제한된 실행 환경에서 `os.replace` 권한 오류가 발생했다. 원자적 저장을 약화하지 않고 같은 검사를 일반 실행 권한으로 수행하여 통과했다.
- 캐시 임시 파일 정리 실패가 계산 결과까지 실패시키는 경우를 보완했다. 저장 실패 후에도 계산 결과와 이전 정상 파일을 보존하는 회귀 검사를 추가했다.
- ndarray 서브클래스의 메모리/디스크 표현 차이를 발견하여 지원 대상을 일반 ndarray로 명확히 제한하고 예외 검사를 추가했다.
- 독립 리뷰에서 ZIP의 메타데이터/결과 멤버가 NPY 배열이 아닌 bytes일 때 `AttributeError`로 재계산이 차단됨을 발견했다. 두 실패를 먼저 재현한 뒤 타입 검사로 cache miss 처리하도록 수정했고, 재계산 1회와 새 관리자에서 디스크 복원까지 회귀 검사했다.
- 레지스트리 독립 리뷰에서 한 개념이 여러 Python 파일·함수·노트북 코드/설명 셀에 연결되는 6개 위치를 확인했다. 셀 ID 변경 시 불일치 탐지도 확인했다.
- Windows 노트북 검사에서 기존 ZMQ event loop 경고는 있었지만 노트북 실제 실행을 포함한 모든 검사는 통과했다.

## 구현 범위와 남은 사항

- `src/utils/`: math, numerical, random, plotting, cache_manager. 수학 배열은 입력 shape 유지, 격자는 `(points, points)`, 중심차분은 스칼라다.
- 캐시는 배열 shape/dtype과 중첩 JSON/tuple을 보존한다. 크기는 항목 수로 제한하고 동시 접근에는 외부 조정이 필요하다.
- `.agent/registry.json`과 `scripts/update_registry.py`를 추가했다. 코드·노트북 변경 후 갱신하고 JSON도 함께 커밋한다.
- 미션별 선형대수·미적분·최적화 본체와 노트북은 이번에 구현하지 않았다. 다음은 Step 2 이슈 #5다.
- PR 검토·병합 상태와 선행 PR 의존성은 이슈 #4 및 전체 계획에서 확인한다.
