# 이슈 #29 — 재평가 60% 원인 분석과 증거 안내

2026-11-08(KST). 사용자는 Naito_AI_eval_result.md를 새 결과로 갱신하고 93%에서 60%로 하락한 이유와 대책을 요청했다. 이후 원문이 지정한 그림 폴더, 이전 PASS가 FAIL로 바뀐 직접적인 근거, 가능한 개선을 확인하도록 강조했고 이번 작업도 main 병합까지 명시 승인했다. 기준 main은 d43b076319ac7fcf1bde5f1fecf48188bd00727a, 작업 브랜치는 codex/29-reevaluation-analysis, [이슈 #29](https://github.com/ntt65/A2_1/issues/29)다.

## 계획과 범위

기초·상세·실행계획을 이슈에 기록하고 전용 브랜치를 만들었다. 두 평가 원문 보존, 15항목 변화, 이전/현재/원격 main의 실제 산출물 대조, 확인 사실과 가설 분리, 제출 대책 및 README 최신 상태 정리를 수행한다. 새 수학 구현·노트북·산출물 변경·외부 평가 실행은 포함하지 않는다.

## 확인 결과

- 시각 순서는 11:52:57의 93%(14/15) → 12:58:12의 60%(9/15)다. #4·#7(원문 번호 누락)·#8·#10·#13·#15가 PASS→FAIL, #3이 FAIL→PASS, 8개 PASS 유지다. 14−6+1=9다.
- 새 FAIL 6개의 근거는 수치 오답이 아니라 증거 부재다. 두 노트북과 기존 관련 PNG·역전파/최적화/확률 JSON은 이전 main 3f03488과 바이트가 동일하다. 선형대수 JSON의 SVD/변환 부분도 동일하다. #23 f435dd4 이후에도 해당 핵심 산출물은 그대로다.
- 원격 main API의 SHA가 로컬 기준과 일치했고 Git tree에서도 파일을 확인했다. 병합 12:53:54는 평가 12:58:12보다 앞선다. 실제 평가 대상 SHA·수집 파일 목록은 원문에 없어 동일 입력 여부는 미확인이다.
- 기존 평가 #4는 rank10/50/100 결과를 인정했고 #8은 four_decimal_match=true를 직접 인용했다. #13도 PNG 파일명 2개를 인용했다. 새 평가에서 이를 없다고 판단한 모순을 기록했다. #7·#15는 이전에도 유도 부족을 지적하면서 PASS를 줬으므로 평가 기준의 비일관성도 조사해야 한다.
- 미션 149행은 outputs/PNG를 지정하며 현재 PNG 15개가 존재한다. 노트북 이미지 내장은 필수 요구가 아닌 조건부 보조책이다. 기존 폴더를 유지한다.
- 역전파 노트북은 15셀/code8/count1~8/stream출력5/error0, 확률 노트북은 19셀/code9/count1~9/stream출력8/error0이다. 이미지 출력 MIME은 0개이며 분포 그림은 상대경로 Markdown이다. 이 형식의 추출 누락 가능성은 있지만 평가기 로그 없이 단정하지 않는다.
- 새 #3이 새 eig JSON을 직접 인용하므로 일부 업데이트가 전달됐다는 근거는 있다. 전부 구버전, 길이 제한, 보너스가 원인, 캐시 문제, 평가기 버그 등을 확정하지 않았다.

## 대책과 변경 파일

Naito_AI_eval_result.md의 최신 상태를 60%로 갱신하고 두 원문을 보존했다. 15항목 변화표와 직접 인용 모순, 사실/원인 가설, 우선순위별 확인 절차를 기록했다. 루트 MISSION_EVIDENCE.md에는 실제 수치·노트북 셀·기본 그림·핵심 유도를 모아 긴 평가 이력과 분리했다. README 앞부분에서 이 요약을 연결하고 외부 재평가 미실행/93% 현재형 문구를 정정했다. PROJECT_PLAN과 본 기록을 갱신했다.

수학 기준은 변경하지 않았다: GD theta_next=(1−2lr)theta, 수렴 반경 .1, SVD 64/128 두 실험, 역전파 벡터 (2,)/행렬 (2,2), 고정 분산 Gaussian NLL과 MSE의 같은 최소점. 전체 h 격자 오차가 전부 1e-4를 통과한다고 쓰지 않았다. 레지스트리 대상 Python/노트북 변경이 없어 재생성하지 않고 정합성만 확인한다.

## 검증·게시 기록

사용자의 README 원인 가설과 기본/보너스 분리 지시를 추가 반영했다. Git 비교에서 보너스 직전197행→직후214행, 기본 결과표106행→123행, 파일 크기23,133→24,931바이트를 확인했다. 최초 비교 main의 결과표는77행이었다. 증거 링크는 삭제되지 않았고 역전파·유도 링크는24→26행에 유지됐다. README만 바뀐 것은 아니며 보너스 커밋은28파일 변경이다. 읽기 제한이 확인되지 않아 원인을 단정하지 않는다.

README7행에서 기본 증거 절을 시작하고 11행부터15항목 표를 배치했다. 또한 기본 실행법·결과·유도를 앞에 유지했다. 평가 이력을 뒤로 보내고 보너스는 문서 마지막의 별도 절로 이동했다. 기존 고유 링크93개를 모두 보존하고 기본/보너스 검증 기록도 분리했다. 첫 게시 커밋22f4a65의 Windows/Linux CI 성공 후 이 사용자 추가 지시를 반영한 후속 커밋을 같은 PR에서 다시 검사한다. 재배치 후5문서의 로컬 링크153개 및 원문·수치·15개 기존산출물 보존을 다시 확인했다.

독립 에이전트 3개가 노트북/유도, 최적화/SVD, 평가 문구/원격 tree를 각각 읽기 전용 검토했다. 두 평가 원문은 첨부 및 이전 문서의 원문 블록과 줄바꿈 정규화 후 완전 일치했다. 사용자가 다시 첨부한 60% 텍스트도 첫 첨부와 동일했다. 프로그램으로 PASS 수 14→9와 변경 7개 항목을 확인했다. 레지스트리 정합성과 git diff 검사를 통과했다.

추가 문서 감사에서 5개 문서의 로컬 링크 156개, 두 원문 보존, 이전 main과 동일한 산출물 15개(노트북2·JSON3·기본PNG10), 주요 수치와 노트북 실행 상태를 확인했다. 전체 PNG는 보너스 포함15개다. 첫 링크 검사는 유효한 디렉터리 링크를 파일로만 검사해 실패했으며 파일/디렉터리 존재 검사로 바로잡은 뒤 모두 통과했다. 구현 실패를 숨기거나 수치 허용오차를 바꾸지 않았다.

명령은 프로젝트 Python의 임시 문서 감사 스크립트, python -m pip check, python scripts/update_registry.py --check, git diff --check다. Windows/Python3.11.4/NumPy2.2.6 환경에서 모두 통과했고 레지스트리49파일/72개념은 변경 없이 일치했다. 재현 가능한 주요 감사 방법은 git show 3f03488:<경로>와 d43b076:<경로>의 바이트 비교, JSON 필드 대조, 노트북 count/outputs 검사 및 PNG 헤더 확인이다.

직전 main 186개 CI 통과는 기존 검증 이력이며 이번 로컬 재실행으로 기록하지 않는다. 커밋·PR·원격 전체 CI·사용자 승인 main 반영은 [이슈 #29](https://github.com/ntt65/A2_1/issues/29)에 누적한다.

남은 확인 사항은 평가 서비스의 실제 입력 SHA/파일 목록/추출 오류와 동일 입력 재평가다. 내장 이미지 제출 노트북/HTML 등 추가 형식 구현은 필요성이 확인된 후 별도 작업으로 진행하며 이번에는 계획만 제시했다. 외부 점수는 최신 60% 그대로이며 15/15 회복을 주장하지 않는다.
