## D03 — 알고리즘 제한과 개발 도구의 역할을 구분한다

**결정:** 수학 알고리즘은 NumPy만 사용하고, 시각화는 Matplotlib·Seaborn을 사용한다. Python 표준 라이브러리는 경로·파일·JSON·해시 등 운영 기능에 사용할 수 있다. 테스트·노트북 실행 도구는 개발용 의존성으로 관리하며 수학 구현을 대신하게 하지 않는다. `np.linalg.svd`는 이미지 저랭크 근사에 허용한다. `np.linalg.eig`는 Power Iteration의 결과 비교 검증에만 허용한다.

**이유:** 원문은 Power Iteration을 직접 구현하도록 제한하지만 SVD 자체를 직접 구현하라고 요구하지 않는다. 캐시와 레지스트리를 만들기 위해 표준 라이브러리 사용도 필요하다. 시각화 도구의 간접 의존성이 설치되었다는 사실과 그것을 알고리즘 구현에 사용하는 행위는 구분한다.

## D04 — seed는 실행 경계에서 설정한다

**결정:** 독립 실행 스크립트, 테스트 준비 과정, 노트북의 재현 가능한 시작점에서 공통 함수로 `np.random.seed(42)`를 호출한다. 모듈 import나 매 수학 함수 호출에 seed 재설정을 넣지 않는다. 테스트는 필요에 따라 각 테스트의 난수 시작 상태를 명시한다.

**이유:** import마다 전역 seed를 바꾸면 다른 계산의 난수 상태에 영향을 준다. 재현에는 seed 외에도 입력, 라이브러리 버전, 실행 순서가 필요하므로 함께 기록한다.

## D05 — 캐시는 로컬 계산 재사용에 한정한다

**결정:** Redis 서버를 도입하지 않고 메모리·디스크의 키-값 캐시를 사용한다. 키에는 계산 버전, 입력 값, 배열 shape·dtype, 관련 매개변수를 포함한다. 난수로 생성된 결과를 캐시하면 seed 또는 생성된 입력 자체도 구분한다. 디스크 저장은 JSON·NumPy의 안전한 형식을 사용하고 비신뢰 pickle은 읽지 않는다. 원자적 저장, 손상 시 재계산, 반환값 변경 보호, 정리 정책을 포함한다.

**이유:** SVD·등고선 격자 등 반복되는 비싼 계산에 우선 적용하면 충분하다. 계산 캐시는 계산량을 줄이며, 코드 탐색에 드는 토큰은 다음 결정의 색인과 검색 범위 제한이 줄인다. 작은 순수 함수까지 모두 캐시하지 않는다.

## D06 — 레지스트리는 검증 가능한 탐색 보조 자료로 사용한다

**결정:** `.agent/registry.json`에 파일→심볼/개념과 개념→파일/심볼/의존성의 색인을 둔다. 심볼명과 파일 경로를 기준으로 삼고 파일 해시로 변경을 감지한다. 줄 번호는 갱신 가능한 보조 위치로 취급한다. 노트북은 셀 ID·제목을 사용한다. 일반 탐색은 레지스트리를 먼저 읽되 초기 생성·누락·불일치 복구에는 범위를 제한한 검색을 허용한다.

**이유:** 줄 번호는 편집만으로 바뀐다. 레지스트리가 없거나 오래됐을 때도 검색을 금지하면 작업이 막히거나 잘못된 위치를 수정하게 된다. 변경된 파일을 중심으로 색인을 갱신하고 전체 파일을 반복해서 읽지 않는다.

## D07 — 면적은 행렬식의 절댓값과 비교한다

**결정:** 비특이 행렬의 면적비는 `abs(det(A))`를 기준으로 상대오차 1% 이내인지 검사한다. 면적 자체는 다각형 좌표로 계산한다. 행렬식이 0인 사례는 별도 절대오차 기준으로 검사한다. 음의 행렬식은 방향 반전 정보로 설명한다.

**유도:** 선형 변환의 부호 있는 면적 배율은 `det(A)`이며 기하학적 면적은 음수가 될 수 없다. 따라서 면적비에 음의 행렬식을 직접 비교하거나 영행렬식으로 나누는 검증은 부적절하다.

## D08 — Power Iteration의 목표와 수렴 범위를 명시한다

**결정:** 목표는 절댓값이 가장 큰 고유값과 대응 고유벡터이다. 검증 기본 행렬은 원문의 실수 대칭 행렬 `[[4,1],[1,3]]`로 고정한다. 최대 반복 수와 수렴 여부를 노출하며 고유값 오차와 잔차를 함께 검사한다. 음의 지배 고유값에서는 부호를 보존하고, 고유벡터의 부호 반전은 같은 고유공간으로 취급한다.

**이유:** 일반 Power Iteration은 대수적으로 가장 큰 고유값을 항상 찾지 않는다. 지배 고유값의 절댓값 분리와 초기 벡터의 성분이 수렴에 영향을 준다. 원문의 반복 횟수 예시는 구현의 종료 조건·초기값에 따라 달라지므로 정답 기준으로 삼지 않는다.

## D09 — SVD 이미지 크기와 rank 충돌을 두 실험으로 해결한다

**원문 충돌:** 기능 요구는 `k=10,50,100` 비교이고 데이터 가이드는 64×64 이하 grayscale 이미지이다. `min(m,n)<=64`이면 rank 100 근사를 독립적인 rank 조건으로 실험할 수 없다.

**결정:** 64×64 grayscale 본 실험은 `k=10,50,64`로 수행한다. 별도 합성 128×128 grayscale 보충 실험을 만들어 `k=10,50,100`을 비교한다. 두 그림 모두 입력 크기와 목적을 표시한다. API에 잘못된 rank를 전달하면 예외를 발생시키며 `min(k,min(m,n))`로 조용히 보정하지 않는다.

**영향:** 두 원문 조건을 단일 실험에서 동시에 만족한다고 주장하지 않는다. 작은 이미지 조건은 본 실험으로, 지정 rank 비교는 크기 예외를 명시한 보충 실험으로 다룬다. 또한 `k(m+n+1) >= mn`이면 SVD 인자 저장량이 원본보다 작지 않으므로 그 경우를 저장 공간 절감이라고 설명하지 않는다.

## D10 — 원형 함수의 학습률 발산 조건을 정정한다

**원문 충돌:** `f(x,y)=x²+y²`에 대해 “lr=0.5 이상에서 발산”은 주어진 GD 식과 일치하지 않는다.

**직접 유도:** `theta_next=theta-lr*(2theta)=(1-2lr)theta`. 원점이 아닌 시작점에 대해 수렴 조건은 `|1-2lr|<1`, 즉 `0<lr<1`이다. `lr=0.5`이면 한 번의 업데이트로 원점에 도착한다. `lr=1`이면 부호만 반전하며, `lr>1`이면 norm이 증가한다.

**결정:** 수렴 실험은 원문대로 `lr=0.1`, 초기점 `(5,5)`, 100회로 수행한다. 추가 비교는 `lr=0.5`, `1.0`, `1.1`로 고정하여 즉시 수렴·진동·발산을 각각 보여준다. 원문의 잘못된 발산 조건에 맞추려고 gradient나 함수를 바꾸지 않는다.

**참고 수치 정정:** GD의 각 좌표는 100회 후 `5*(0.8)^100 ≈ 1.018517988e-9`이다. 원문의 `(0.08,0.08)`은 이 조건의 계산 결과가 아니므로 복사하지 않는다. 이 값은 반복식의 닫힌 해를 평가한 문서 기준이며 구현 테스트 통과를 의미하지 않는다.

## D11 — Momentum 비교는 실측 결과로 판단한다

**결정:** `v_next=beta*v+gradient(theta)`, `theta_next=theta-lr*v_next`, `v_0=0`을 사용한다. `(1-beta)`를 gradient에 곱하는 다른 관례와 혼합하지 않는다. 비교에는 같은 초기점·목적함수·반복 예산을 사용하고 학습률과 beta를 공개한다. 원문 설정의 비교를 먼저 수행하고, 추가 실험은 별도 설정으로 기록한다.

**직접 유도:** `x²+10y²`의 Hessian은 `diag(2,20)`이다. Vanilla GD의 양의 학습률 수렴 범위는 `0<lr<0.1`이다. 원문의 `lr=0.05`에서는 y 좌표가 한 번에 0이 되므로 그 축에 계속 지그재그가 생긴다고 가정하지 않는다. Momentum의 각 고유방향은 `r²-(1+beta-lr*lambda)r+beta=0`의 점화식으로 해석할 수 있으므로 초기 진동과 이후 수렴 속도를 구분한다.

**이유:** Momentum이 모든 설정·매 반복에서 더 빠르거나 경로가 더 부드럽다는 보장은 없다. 원문의 설명 문구를 목표로 그래프나 수치를 고르지 않는다. 목적함수·gradient norm·도달 반복 수 등 실제 결과를 근거로 이점과 한계를 설명한다.

## D12 — 역전파는 고정 예제를 유지하고 참고 수치를 재계산한다

**결정:** `x=[1,0]`, `W1=[[0.1,0.2],[0.3,0.4]]`, `b1=[0,0]`, `W2=[0.5,0.6]`, `b2=0`, `y_true=1`을 변경하지 않는다. `z1=W1@x+b1` 방향을 유지한다. 중간값을 조기에 반올림하지 않고 마지막 표시에서 네 자리로 반올림한다.

**직접 유도:** `a1=sigmoid([0.1,0.3])`, `z2=0.5*a1[0]+0.6*a1[1]`, `delta2=sigmoid(z2)-1`, `delta1=(delta2*W2)*a1*(1-a1)`이다. 따라서 `z2≈0.607155103826`이고 `delta1≈[-0.043978515809,-0.051733504391]`이다.

**원문 참고치 정정:** `z2`의 네 자리 반올림은 `0.6072`이며 원문의 `0.6071`과 다르다. 두 번째 은닉 기울기는 `-0.0517`이며 원문의 `-0.0513`과 다르다. `dL/dW1` 두 번째 행 첫 원소에도 같은 정정이 적용된다. 원문 자체가 결과 예시는 정답이 아니라고 명시하므로 수식에서 재계산한 값을 기준으로 사용한다.

**검증 방식:** 손계산 유도를 먼저 독립적으로 작성하고 충분한 정밀도의 기준값을 고정한 뒤 NumPy 결과와 비교한다. 절대오차 `<=5e-5` 및 네 자리 반올림 표시의 일치를 함께 확인한다. 추가 중심차분 검증으로 같은 잘못된 식을 양쪽에 복제하는 위험을 줄인다. Step 0에서 계산한 기준값은 알고리즘 구현·테스트 통과 결과가 아니다.

## D13 — 확률 표기와 MLE의 가정을 고정한다

**결정:** 정규분포 표기는 `N(mu,sigma²)`를 사용한다. 따라서 원문의 `N(2,0.5)`는 평균 2, 분산 0.5이다. 자연로그를 사용한다. Gaussian MLE와 MSE의 연결은 독립 오차와 고정된 양의 공통 분산을 가정한다. Bernoulli의 BCE와 categorical의 Cross-Entropy는 각각 유도한다.

**이유:** 두 번째 인자를 표준편차로 읽으면 다른 분포가 된다. Gaussian 음의 로그우도는 MSE와 상수·양의 계수 차이가 있으므로 같은 최적해를 갖는다는 뜻이지 항상 같은 값이라는 뜻은 아니다. 분산이 입력이나 매개변수에 따라 달라지면 추가 항을 무시할 수 없다.

**안정성:** Softmax는 최댓값을 빼서 계산한다. Sigmoid+BCE의 수치 계산은 안정적인 logit 표현과 대응 gradient를 사용한다. 확률을 무조건 clipping한 손실에 원래 함수의 미분을 그대로 붙여 경계에서 서로 다른 함수를 검증하지 않는다.

## D14 — 검증 사실과 보고 구조를 일치시킨다

**결정:** 완료 보고에는 작업 이슈·브랜치·PR, 적용 수식·가정, 변경 파일·shape, 실제 검증 결과·보완, 레지스트리 갱신, 남은 사항을 포함한다. 환경 준비에서는 수식·shape를 해당 없음으로 기록할 수 있다. 실행하지 않은 항목은 통과로 표시하지 않는다.

**이유:** 원래 네 항목 형식만으로는 사용자가 요구한 전체 작업 이력과 push·PR 상태가 빠진다. 로그는 재현 가능한 명령과 핵심 결과를 중심으로 남기고, 인증 정보나 무관한 원본 출력은 기록하지 않는다.

## D15 — 평가 권고는 실측 증거와 적용 범위를 구분한다

**결정:** Naito_AI의 PASS 권고도 검토하되 64×64는 SVD 입력 배열 가이드로 해석한다. PNG 캔버스·패널·DPI는 서로 다른 값이며 읽을 수 없는 64px Figure로 축소하지 않는다. 역전파·MLE 유도는 기존 노트북과 일반 Markdown에서 함께 제공한다.

**실험 기준:** 결정론적 최적화의 동일 입력 재시도 평균 대신 사전에 고정한 여러 초기점의 민감도를 측정한다. 반경 0.1 첫 진입과 기록한 예산 끝까지 유지하기 시작한 시점을 구분하고 미도달은 null로 기록한다. 성공 표본의 도달 반복수 평균·분산은 성공수/전체수와 함께 제시한다. 유한 관측 구간의 유지를 무한 시간 수렴 보장으로 표현하지 않는다.

**수치 해석:** `x²`의 중심차분은 정확 연산에서 절단오차가 0이다. 격자상 최소오차 h와 통과한 표본 구간은 해당 함수·점·dtype의 결과이며 보편적인 최적 간격이 아니다. 실패 진단은 명시적으로 주입한 잘못된 값으로 재현하고 실제 알고리즘 실패와 구분한다. 자체 검증 결과는 외부 재평가 점수가 아니다.
