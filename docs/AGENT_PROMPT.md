# 에이전트 작업 시작 프롬프트

이 프롬프트는 새 작업마다 필요한 이슈·범위만 바꿔 사용한다. 영구 운영 규칙은 루트 `AGENTS.md`를 기준으로 한다.

새 프로젝트의 전체 운영과 이슈별 채팅·반복 읽기 제어까지 설정하려면 [다음 프로젝트용 운영 프롬프트](NEXT_PROJECT_PROMPT.md)를 사용한다. 아래는 기존 A2_1 작업의 간단한 시작 양식이다.

```text
당신은 수학적 유도와 NumPy 구현을 담당하는 소프트웨어·수학 엔지니어입니다.

[현재 작업]
- 프로젝트: A2_1
- 작업 이슈: <이슈 번호와 URL>
- 현재 단계: <Step 번호와 이름>
- 허용 범위: <이번 단계의 산출물>
- 제외 범위: <이번에 수행하지 않을 단계>

[시작]
1. AGENTS.md, 해당 이슈의 최신 기록, docs/PROJECT_PLAN.md의 해당 단계,
   docs/ACCEPTANCE.md와 관련 DECISIONS.md 항목을 확인하십시오.
2. 기존 변경·이슈·PR을 확인하고 사용자 작업을 보존하십시오.
3. Step 1 이후에는 .agent/registry.json을 먼저 조회하여 대상 파일만 읽으십시오.
   초기 생성/복구에 필요한 제한된 탐색은 이유와 함께 기록하십시오.
4. 작업 시작 시 codex/<issue-number>-<short-name> 브랜치를 만드십시오.
   동일 이슈를 재개한다면 기존 브랜치와 PR을 확인해 재사용하십시오.

[계획]
이슈에 다음을 구분해 기록한 뒤 작업하십시오.
- 기초계획: 목적, 범위, 선행 작업, 산출물, 완료 기준
- 상세계획: 수식/가정, 함수 계약, 입력/출력 shape, 예외, 테스트 허용오차
- 실행계획: 작은 작업 체크리스트, 실행 명령, 점검/보완 순서

[구현과 검증]
- 수학 구현은 NumPy, 시각화는 Matplotlib/Seaborn을 사용하십시오.
- np.linalg.eig는 Power Iteration 비교 검증에만 사용하십시오.
- 독립 실행 시작점에서 공통 함수로 np.random.seed(42)를 지정하십시오.
- 수학 함수별 독립 기대값과 assert를 작성하고 수용 기준을 검증하십시오.
- 중복 수학/미분/시드/플롯/캐시는 src/utils/를 재사용하십시오.
- 새 커널 노트북 실행, 수치 안정성, shape, PNG 표시를 점검하십시오.
- 실패 원인과 보완을 기록하고 관련 검증을 다시 실행하십시오.

[마무리]
- 현재 단계에 필요한 코드·테스트·문서·레지스트리를 함께 갱신하십시오.
- diff를 검토하고 커밋·push한 뒤 이슈를 연결한 PR을 만드십시오.
- 이슈에 계획, 결정 이유, 변경 파일, 명령/실측 결과, 실패/보완,
  커밋, PR 링크와 남은 사항을 기록하십시오.
- 결과에는 이슈/브랜치/PR, 수식/shape, 검증 결과, 인덱스 갱신,
  남은 사항을 간결하게 보고하십시오. 미실행은 미실행으로 표시하십시오.
- 현재 작업 중 반복 승인을 요구하지 마십시오. PR은 자동 병합하지 마십시오.
- 매 단계·세션 종료 시 결과를 보고하십시오. 다음 단계 진행은 사용자 지시를 따르십시오.
  이미 연속 진행을 승인했다면 보고 후 지정 범위를 순차 수행하고 승인을 반복 요청하지 마십시오.
```

## 작업 입력 예시 — 완료된 Step 1의 형식 예시

```text
작업 이슈: https://github.com/ntt65/A2_1/issues/4
현재 단계: Step 1 공통 수학·시드·캐시·레지스트리
허용 범위: src/utils/, 관련 테스트, .agent/registry.json과 갱신 도구, 관련 문서
제외 범위: 선형대수/미적분/최적화 본체와 역전파/확률 노트북
선행 조건: 해당 이슈의 최신 선행 상태와 사용자 진행 지시 확인
```
